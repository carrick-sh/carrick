# Native-child entropy (#1338)

`kernel.native.entropy` requires a fork child to receive entropy through its
own authenticated service custody while its parent remains alive. The native
Linux authority is [getrandom(2)](https://man7.org/linux/man-pages/man2/getrandom.2.html).
Carrick remains experimental; these witnesses do not establish full Linux
coverage or a hardened trust boundary.

## ARM transport

The native ARM exit stages ordinal 278 as a typed entropy request instead of
an ordinal-only Crossing. The ring owns a record bounded to 4096 output bytes.
The child's exact MM prepares the accessible output prefix before publication,
including COW preparation. A preparation refusal yields through the existing
service owner and retries before generating bytes. Invalid flags reach the
shared handler before any output-memory error.

The HVF intake retains the staging backing under the authenticated member/MM
identity. Its adapter invokes the existing `proc::getrandom` algorithm using
bounded staging memory. The user-memory and staging adapters share flags,
source failure, and random generation semantics. Staging does not impersonate
the root task or access root guest memory. The reply is published before the
same ticket is acknowledged.

Completion retains generated bytes and a page cursor through Busy/OwnerWait.
Copyout revalidates the exact child MM. A genuine copy fault reports errno 14
before the first byte, or the committed prefix afterward. Cancellation before
a reply returns errno 4; cancellation after a valid reply preserves generated
bytes. Terminal cancellation keeps the existing retirement policy. A staging
request serves at most one 4096-byte chunk and can return a bounded short read
for a larger request; no guest-sized allocation is made.

The two ARM production-fork witnesses are enabled and extended through service
completion and native resume. Host test support uses the existing handler on
the ring-owned staging. Additional service witnesses cover first-byte EFAULT,
accessible-prefix short read, flags before memory faults, stale MM incarnation,
Busy/OwnerWait after a committed page prefix, and cancellation before/after
reply. Deterministic retention tests use supplied bytes to distinguish replay
from fresh generation; they are not RNG quality tests.

## Protocol and authority

Entropy operation kind 7 uses no file or exec capability. Its descriptor checks
non-null staging, address overflow, and record lengths from 32 through 4128.
The record has magic `CENT`, version 1, opaque 32-bit flags, capacity, signed
result, state and a zero reserved word. Checked decoding rejects malformed
states, lengths, reserved fields and counts outside the capacity or errno
range. The service ticket binds birth, member, MM incarnation, execution and
sequence. A descriptor alone still cannot enter the native service: admission
requires its exact ring-owned allocation.

## Remaining physical evidence and x86

Signed HVF, Node/OpenSSL and runtime ratio checks are UNRUN (director). VM-free
ARM tests do not prove physical HVF execution. The ignored x86 KVM witnesses in
`cpl0_initial_mm` remain red: native Linux exits 8, the prior KVM run exited
218 (errno 38 modulo 256). x86 still needs CPL0 selection of entropy, a
physical service doorbell/intake with retained staging, a host adapter using
the shared handler, and ticket acknowledgment/resume. Merely allowing
`CompletionRoute::NativeService` is insufficient. Socket and mmap are outside
this entropy slice and unchanged.

## Earlier root-handler red-first evidence

Conflicting flags 6 and 7 returned zero at length zero before the root fix;
native Linux returned errno 22 at lengths zero and eight. Source-failure
injection previously returned eight on first-fill failure and 8192 on a
second-fill failure. The fixed handler returns errno 5 before any commit or
the already committed 4096-byte prefix. The deterministic fallback was removed.
Docker differential remains unrun.

## Flags argument width

The existing handler also rejected high register bits that Linux ignores:
`getrandom` takes `unsigned int flags`. Native x86_64 Linux returned zero or
eight bytes for valid low flags with bit 32, bit 63 or all upper 32 bits set.
Low flags 6 and 7 (conflicting sources), and 8 (unknown flag), still returned
errno 22 regardless of those upper bits. A 72-case raw-syscall diagnostic
checked both lengths and all those patterns, including a zero upper word.

The production-dispatch witness
`getrandom_flags_use_linux_unsigned_int_width` was red at
`flags=0x100000000, length=0`: errno 22 instead of zero. The handler now
narrows the flags argument to its Linux width before validating supported
bits and conflicting sources. The witness checks 54 combinations, requiring
no preparation for zero lengths or invalid flags, one preparation for an
eight-byte valid request, and an unchanged buffer suffix. This handler
correction does not serve a native child's request.

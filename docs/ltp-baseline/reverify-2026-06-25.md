### _64 pair diagnoses (oracle-verified 2026-06-25 — all MEDIUM-deep semantic, not clean)
- **pwrite04/_64**: pwrite to an O_APPEND fd must append at EOF ignoring the passed offset (Linux);
  macOS pwrite honors the offset. Fix in the pwrite handler: if fd is O_APPEND, write at EOF (the test
  checks file size, not offset; for fidelity, restore the offset after).
- **sendfile04/_64**: a source buffer with restricted memory protection (PROT_NONE etc.) must give
  EFAULT; carrick doesn't enforce mmap protection on the sendfile read path (related to mmap05/13
  PROT_NONE/SIGBUS enforcement gap).
- **fcntl15/_64 + fcntl37/_64**: re-locking a just-UNLOCKED record region returns EAGAIN — carrick's
  F_SETLK F_UNLCK isn't releasing the lock (record-locking state bug). Medium-deep.
- **statfs02/_64**: F1 is the ELOOP (symlink-loop) case, like statvfs02 — path-resolution.
LESSON CONFIRMED 3x this turn (epoll_ctl05 ELOOP≠EPERM, statfs03 EACCES≠path-val, _64 pairs semantic):
ALWAYS `docker run … <test> | grep TPASS` for the exact expected errno BEFORE coding — the TFAIL text
("succeeded"/"expected EINVAL") does NOT reveal the root.

### net cluster diagnoses (oracle-verified 2026-06-25 — medium errno/validation, shared roots)
- **socket01 + socketpair01** (shared root): socket()/socketpair() with invalid domain/type/protocol
  must return Linux errnos (invalid type→EINVAL, bad protocol→EPROTONOSUPPORT) — carrick forwards the
  macOS errno (gets EPROTONOSUPPORT/EPERM where Linux gives EINVAL/EPROTONOSUPPORT). Fix: map the macOS
  socket-creation errno to Linux per invalid-arg case. +2.
- **setsockopt01 + getsockopt01** (shared root): on a bad fd → EBADF, non-socket fd → ENOTSOCK, BEFORE

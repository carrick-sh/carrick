# carrick-embed Phases A–C Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the independent fixes the embed survey surfaced (Phase A), make the container a kernel-graph object so one carrier hosts many containers as namespace trees (Phase B), and ship `carrick-embed` v1 — typed engine `RunRequest`, `Runtime::prepare`/`PreparedRun`, stdio sink, builder, result/error types, a signed fail-closed test lane and `TestContainer` (Phase C).

**Architecture:** `ContainerBuilder → carrick_engine::RunRequest → Engine::resolve → RunSpec → Runtime::prepare(spec, LaunchContext, RuntimeExtensions) → PreparedRun::execute → RunResult`, on one HVPatch carrier / one HVF VM / one kernel graph in which each run is a `Container` object owning its pid region, clock domain, granted caps and (later phases) mounts, observers and quotas. Process statics and env-carried identity are replaced by the `Container`/`LaunchContext` pair; carrier-lifetime infrastructure stays explicitly process-scoped.

**Tech Stack:** Rust 2024 workspace; HVPatch kernel (`carrick-runtime`, `carrick-kernel`, `carrick-vmm-hvf`, `carrick-mem`); `carrick-engine`/`carrick-spec`/`carrick-image`; `just` recipes; Apple `ld64` + `codesign` with `scripts/entitlements.plist`; the Docker native-arm64 oracle and `crates/carrick-cli/tests/conformance.rs` probe gate; DTrace via `carrick trace`.

**Spec:** [`../specs/2026-08-25-carrick-embed-program-design.md`](../specs/2026-08-25-carrick-embed-program-design.md) — read it first; this plan argues from it.

**Line numbers:** every `file:line` below was verified against `39426141` (2026-08-25). `main` moves daily; the quoted "existing text" is the authority — re-`grep` before editing and expect ±tens of lines.

## Global Constraints

- HVPatch is the only execution model; never revive host-process-per-guest-process paths. No `libc::fork` in runtime production code; `scripts/migrate/check-carrier-only-process-invariant.py` and `check-host-authority-transitions.py` auto-scope every crate and must stay green (`just lint-domains`, inside `just ci`).
- Typed domains: no bare `u64`/`i32` crosses a semantic boundary (use `Fd`/`HostFd`, `NsPid`/`HostPid`, `Signal`, `GuestVa`/`Gpa`/`HostVa`, `LinuxErrno`, `CanonicalNr`/`NativeNr`, `TaskKey`, and the new `ContainerId`/`RunId`). ABI constants live in `carrick-abi`; no column-0 `const LINUX_*` in dispatch files.
- No backward compatibility, no V2-beside-V3, no shims: replace and delete. Opt-OUT not opt-in: new mechanisms default ON with an exact `=0` escape hatch.
- With no extensions installed, the syscall hot path gains no heap allocation, lock, trait call, payload decode or formatting — only `Option` branches; every phase records a same-artifact ABBA + DTrace receipt.
- TDD, red-first: every task begins with a failing test (or, for deletions, a grep assertion that fails before and passes after), proven red against the pre-fix artifact.
- Tests: `just test` (never a bare `cargo test --workspace --lib`; three crates fork from the harness and must run under `RUST_TEST_THREADS=1`). Guest-running tests need a codesigned, hypervisor-entitled executable: `just build`/`just run` for the CLI, and the new `just test-embed` lane (Task 31) for test binaries; `HV_DENIED` (`0xfae94007`) is a FAILURE, never a skip. Never run Carrick and the Docker oracle concurrently; stamp `CARRICK_RUN_ID` and reap with `scripts/sudo/kill.sh <run-id>`.
- Use the `libc` crate, not ad-hoc `extern "C"`. Never read Linux kernel or other GPL source; derive ABIs from man-pages and the Docker oracle.
- Commits: Conventional Commits `type(scope): subject` with a body (Why / What / Verified), `Co-Authored-By:` trailer, `just fmt` before commit, never `--no-verify`. Work on `feat/carrick-embed` in `.worktrees/carrick-embed`.
- Honest status: nothing here is production-ready or a hardened boundary for untrusted code; say so in docs and commit messages.
- Landing order is the task order. Probe-census constants (`PROBE_SOURCE_COUNT`, `DEDICATED_PROBE_RUNNERS.len()`, generic/dedicated totals) are expressed as deltas per task; the absolute values after every Phase A/B probe lands are `PROBE_SOURCE_COUNT = 470`, dedicated `22`, generic `422`, `generic + dedicated == 444`, `2 * (…) == 888`.

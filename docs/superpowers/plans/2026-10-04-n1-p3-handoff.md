## Leaf changes

- `H/foreign_mm/current_read.rs`: keep `LegacyProtectionRead` alive through
  preparation and window copy. An admitted target refuses before the host
  walk. A physical pin alone never grants a live translation or permission.
- `H/foreign_mm/instruction_read.rs`: retain the same legacy authority borrow
  across content observation and its byte read, including deferred recipes.
  Admitted readers refuse before observation/walk; the existing distinction
  between tracked content and executable authorization remains.
- `H/foreign_mm/el1_publication.rs`: retain the existing legacy authority
  borrow in both descriptor service variants, including publisher settlement
  and Drop. Guest descriptor ownership alone cannot authorize host plans
  against an exclusively admitted owner. No refusal chooses a fallback.
- `K/dispatch/proc.rs`: replace the process_vm read/write boolean with
  `ProcessVmDirection`. Privileged ptrace POKE keeps its existing separate
  stopped-target/text authority; this direction grants only ordinary access.
- `K/vfs/proc.rs`, `K/dispatch/fs/ioctl.rs`: extract `ProcMapBounds::render`
  over already observed bounds, preserving heap/arena clamp and page alignment
  for maps text and PROCMAP_QUERY. This is serialization, not an MM lookup,
  residency model, generation receipt or new semantic authority.

No reserved shared source, ABI, module registration, inventory, runtime
binding, `/proc/mem` implementation or embed fixture is edited. Other
construction/backends still use the existing legacy implementation; these
changes add no second transport or replacement owner policy.

## Integrator changes required

The names below that are not present today describe required signatures and
behaviour for n1f to settle in the common seam. They are not helper APIs or
claims that the ABI exists.

### Rows 8/9: one owner service and exact stopped target

1. In `H/foreign_mm.rs`, extend the existing `CarrierForeignMmReadLease`
   authority representation to retain the exact admitted `El1MmHandle` and
   an owned common service capability. Validate carrier, MM incarnation,
   root/ASID generation and physical custody together. Do not retain manager,
   host protection/VMA/COW truth or a guessed VA-to-IPA route in the owner
   variant. Root/ASID identity alone cannot mint a handle.
2. Reuse `A/user_transfer.rs::TransferTarget::from_handle(handle, ttbr0)` and
   the existing `MmPortalSlots`/transfer selection and settlement protocol.
   Its current engine service loan cannot be obtained by these leaf clients.
   In the runtime binding/shared scheduler seam, provide an **owned** service
   loan for the exact target that progresses without running its EL0 task or
   consuming another occupied default executor lease. Retain target admission
   through service/cancellation; use the existing owned wait/release mechanism.
   Do not add a portal, timeout fallback, worker wait or polling loop.
   The present seam is
   `Aarch64EngineCore::transfer_service_loan(&self) ->
   Result<TransferServiceLoan<'_, V>, TrapError>` in reserved `A/engine.rs`.
   Its `RefMut<V::Vcpu>` is tied to the caller engine. Exposing that borrow
   alone cannot represent an owned stopped-target service or suspension.
   Preserve the existing
   `OwnedUserTransfer::advance(&mut self, engine: &Aarch64EngineCore<V>,
   custody: &C, slots: &MmPortalSlots) -> Result<TransferProgress, TrapError>`
   state machine and completed `offset()`: OwnerWait, Physical, Supply and
   Suspended must retain the operation and release executor capacity; Retired
   and Refused retain their distinct target/errno outcomes. Move its service
   binding to the shared owned capability instead of implementing another
   transfer loop in the observer leaf.
3. Keep the existing trait signatures as the consumer boundary:

   ```rust
   ForeignMmReadLease::prepare_read_window(
       &self, invocation: &ForeignMmInvocation,
       authority: &dyn ForeignMmLiveAuthority, snapshot: &dyn ForeignMmSnapshot,
       start: GuestVa, len: usize, deadline: Instant,
   ) -> Result<Box<dyn ForeignMmReadWindow>, ForeignMmTransportError>

   ForeignMmReadWindow::copy_into(
       &self, authority: &dyn ForeignMmLiveAuthority,
       snapshot: &dyn ForeignMmSnapshot, va: GuestVa,
       dst: &mut [u8], deadline: Instant,
   ) -> Result<(), ForeignMmTransportError>
   ```

   The owner window must carry an owner-issued operation/physical retention
   receipt, revalidate the exact incarnation and requested range, and copy
   actual bytes through UserTransfer. Permission decisions and materialization
   remain EL1-owned. Suspension must propagate as an owned continuation through
   the shared consumer interface, rather than lowering Busy/Wait to EFAULT.
   Updating that shared interface is n1f's decision, not a second leaf API.
4. Route existing `read` and `read_instructions` through that same service.
   Instruction reads use existing `PortalTransferIntent::ReadInstruction`,
   preserve execute-only inspection, and retain exact physical content
   dependencies. No host descriptor walk selects the instruction snapshot.
5. Replace `ForeignEl1Publisher::{authenticate,publish}` and
   `ForeignStage1Services::for_target` for admitted operations with this owned
   transfer capability. Delete host transaction preparation/settlement authority
   from the admitted variant, rather than bypassing the new legacy borrow.

This turns the committed checked-window red green. Bind it subsequently to
signed production with actual runtime default-pool exhaustion, two live MMs,
a stopped target and bounded completed copies. The test fixture's empty host
manager must remain empty; adding a mirror/manager is not closure.

### n1g: fence unsupported-window fallback and ordinary reads

The helper does not edit reserved `K/kernel/mm_access/current_read.rs` or
`H/foreign_mm.rs`. These shared corrections are required:

- In `KernelContext::copy_current_into_cached(&self,
  execution: &ThreadExecutionLease, start: GuestVa, dst: &mut [u8],
  cache: &mut CurrentReadCache) -> Result<(), MmAccessError>`, distinguish an
  owner-required refusal from unsupported legacy window support. The current
  match on `ForeignTransport(AuthorityUnavailable)` invokes
  `copy_current_into`. Settle a distinct typed owner refusal in the common
  transport contract; it must never match unsupported-window fallback.
  Propagate the owner's owned continuation where service can wait. Do not
  treat missing owner service as an owner-issued permission decision.
- In `CarrierForeignMmReadLease::read(&self,
  invocation: &ForeignMmInvocation, authority: &dyn ForeignMmLiveAuthority,
  snapshot: &dyn ForeignMmSnapshot, va: GuestVa, dst: &mut [u8],
  deadline: Instant) -> Result<Box<dyn ForeignMmReadReceipt>,
  ForeignMmTransportError>`, fence admitted roots before
  `foreign_stage1_translate` / `copy_from_pinned_owner`. The ordinary route
  must use the same exact-owner UserTransfer permit as window preparation.
  Legacy reads must retain a real legacy-authority guard across selection and
  copying. A physical pin or a readable snapshot cannot authorize that route.
- Apply the same fence to calls reaching `MmAccessAuthority::read_mm` through
  `copy_current_into`, including unsupported multi-page windows and direct
  ordinary reads. Only genuinely unsupported legacy windows may fall back;
  admitted roots may neither host-walk nor copy without an owner permit.

Paired regression layers:
`n1_review_owner_window_refusal_cannot_select_legacy_fallback` checks the real
HVF leaf for resident and multi-page requests;
`n1_review_current_cache_owner_refusal_never_calls_legacy_read` calls the real
kernel cache with an empty cache, asserts unchanged destination bytes and
zero ordinary read callbacks after that refusal, and proves the counter with
an `AuthorityUnavailable` positive control. The kernel fixture uses the
existing scripted transport; it does not connect HVF to the kernel fixture.
The eventual common binding must test that connection with both observer
leases retained simultaneously and successful A/B/A reads, including a stopped
target under default executor-lease exhaustion. Keep both leases across
protect/unmap/exec tests, authenticating the exact affected generation while
the unrelated MM's lease remains valid. That binding turns
`n1_stopped_observer_and_native_lease_use_exact_owner` green and supplies the
remaining native activation/revocation assertions; these regressions alone
do not close the composite owner contract.

### Row 24: ordinary writes and privileged POKE

- Extend the common owner ABI/personality with a separately authenticated
  privileged POKE operation. `PortalTransferIntent` currently contains only
  UserRead, UserWrite, ReadInstruction and CarrickInternalRead. POKE must consume
  the kernel's exact stopped-task/generation authorization; ordinary UserWrite
  must still reject RX/PROT_NONE. Preserve private COW and instruction
  publication without using POKE as guest-store permission.
- `K/dispatch/proc.rs::ProcView::process_vm_rw<M: CurrentMmMemory>` keeps its
  current iovec validation/order and exact completed-prefix semantics. Wire
  `MmAccessAuthority`/`ForeignMmReadLease` to the common service, preserving the
  owned offset, local scatter progress and target endpoint through suspension.
  Unknown/retired target yields ESRCH (3), first inaccessible user byte EFAULT
  (14), later inaccessible byte the actual completed prefix. A resource wait
  is neither a permission fault nor a short successful transfer.
- The ptrace memory arms keep the exact stop witness and use owner POKE; do not
  fold it into `ProcessVmDirection::Write`. Existing
  `process_vm_readv_later_foreign_fault_returns_completed_prefix`,
  `process_vm_readv_foreign_first_fault_returns_efault`,
  `process_vm_readv_stale_target_returns_esrch` and ptrace RX tests must bind
  to the production owner, not just the old test transport.

This supplies the missing prefix/errno/POKE parts of the composite witness.

### Row 25: generation-scoped Observe and /proc/mem

- Replace host tree traversal in
  `K/dispatch/mem/anonymous.rs::owner_observed_rows` and shared MM backend
  observation with one EL1 Observe operation addressed by the exact handle.
  Completion carries that owner incarnation and one observation revision,
  bounded VMA/residency records and its operation identity. All maps/pagemap,
  mincore/status/smaps and PROCMAP_QUERY consumers must use the same receipt.
  No host residency inference or second VMA snapshot becomes authority.
- Preserve `MmBackend::snapshot(&self, deadline: Instant) ->
  Result<MmBackendSnapshot, SnapshotError>` as the existing observation entry
  until its owned-wait result is settled centrally. Validate an owner receipt
  before building `SyntheticProcContext`; the shared
  `FsView::synthetic_proc_context` adapter is reserved. An observation for the
  reader's own MM cannot answer a foreign maps fd, or a successor exec MM.
- `ProcMapBounds::render(start: GuestVa, end: GuestVa,
  used_end: Option<GuestVa>) -> ProcMapBounds` and
  `render_proc_maps_from_regions` serialize the validated observation. Owner
  observations should already contain semantic used bounds; legacy bootstrap
  clamps are not permission/residency policy for an admitted MM.
- In reserved `K/dispatch/fs/rw.rs`, retain an exact target owner/operation for
  `/proc/<pid>/mem` accesses. Use the same transfer service and intentional
  proc-mem access authorization, with correct first fault/partial prefix and
  exec/retirement behaviour. Do not emulate it with host ptrace or raw pointers.

This supplies maps/residency/foreign-fd and /proc/mem composite assertions.

### Row 30 and P2: owner NativeData activation/revocation

- Add distinct common NativeData authorization/receipt, rather than reusing
  UserWrite, a POKE receipt or tracked instruction content as native permission.
- Replace reserved `H/foreign_mm.rs::{CarrierNativeDataSpan::
  validate_native_activation, CarrierForeignMmReadLease::borrow_native_data}`
  host mirror/live-terminal checks with that receipt. Keep exact-generation
  physical pins and content-write exclusion. Activation authenticates target
  task/MM/root/ASID and operation; pointer access cannot outlive its lease.
- Owner protect/unmap and P2 exec prepare/commit/abort must revoke affected
  activations, drain active users through existing content custody, and reject
  stale activation/completion before exposing a pointer. Unrelated-MM leases
  remain valid; abort preserves predecessor bytes/permissions and valid leases
  according to the common transaction outcome. No host semantic registry.

This supplies native protect/unmap/exec and delayed-generation assertions.
Instruction content observation alone is not native activation proof.

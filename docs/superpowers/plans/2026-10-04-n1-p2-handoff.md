## Required common-file integration

The signatures below are **proposed obligations**, not available APIs or a
parallel implementation supplied by this helper. Evolve the existing owner
and transport once; do not add a fallback or second MM policy engine.

1. **Seal the capability pair (rows 1/2/21).** In
   `A/stage1_authority.rs`, `H/foreign_mm.rs::MmAccessState`, and shared
   engine/backend attachments, consume a distinct unpublished
   `BootMmBuilder` in
   `BootMmBuilder::seal(self, owner_completion: SealedOwnerCompletion)
   -> Result<El1MmHandle, SealError>`.
   `SealedOwnerCompletion` must authenticate the exact carrier/MM/incarnation
   and closed root. Consume table image, manager, resolver, undo, arena
   source, image pool and mutable protection/VMA authority before opening.
   Replace `MmAccessState::new`'s admitted capability pair with an owner-only
   constructor, for example
   `MmAccessState::from_owner(handle: El1MmHandle, custody: OwnerCustody)
   -> Arc<MmAccessState>`; its admitted representation must have no
   `Stage1Authority` or method to return one. A separate setup venue can
   accept an unpublished builder, never an admitted handle. Do not merely
   clear the present manager while retaining methods that recreate it.
   Rewrite the active sealed-successor witness to construct through the
   consumed production boot/exec boundary and compile-fence the retired
   pair construction. This turns the ownership red green and closes the
   construction escape it currently demonstrates. Direct conversion
   doctests alone are insufficient.

2. **One owner Exec transaction (row 21).** In the common
   `E/personality/mm_portal` owner and ABI/transport, provide
   `MmPortal::prepare_exec(predecessor: El1MmHandle,
   image: ImmutableExecImage, worker: u32)
   -> Result<PreparedEl1Exec, MmError>`, with owner-only
   `PreparedEl1Exec::commit(self, task_commit: ExactTaskExecCommit)
   -> Result<ExecCompletion, MmError>` and
   `PreparedEl1Exec::abort(self) -> Result<ExecAbortCompletion, MmError>`.
   These signatures name the required typed inputs, not new wire layout.
   The existing portal ring must carry and authenticate them. The owner
   builds the unpublished successor's live tables, VMAs, permissions and
   frame references from immutable ELF/file bytes. The host supplies bytes
   and physical custody only. Commit authenticates predecessor and closed
   successor, composes task/MM publication, and exposes immutable root/ASID
   identity. Abort releases successor references and restores exact
   predecessor bytes/permissions/identity/occupancy at every owner boundary.
   No admitted `prepare_global_exec_plan_with_root_backing`, host image
   snapshots, `replace_for_exec` or predecessor adoption is permitted.

3. **Prepared-copy settlement is part of Exec.** The common owner must
   stop new old-MM permits and revoke/drain each exact admitted operation
   before switching or recycling. A claimed copy cannot be freed while its
   host memcpy owns it. Return the existing typed owner wait/continuation,
   release execution capacity and resume on exact settlement; never park a
   worker, poll, increase a timeout, or synchronously wait in Drop. Abort
   must reject canceled old permits and delayed completions without changing
   predecessor incarnation; an unsuccessful Linux exec preserves that MM.
   The current green witness explicitly calls `cancel_prepared`; it does
   **not** establish automatic Exec revocation. Add failures at owner image
   creation, capacity, live-store/TLBI, task/MM commit and rollback boundaries,
   including a delayed completion after each failure and success. Bind the
   existing physical/permit assertions to this transaction. This is the
   missing full `n1_exec_abort_preserves_exact_predecessor_and_rejects_stale_permit`
   production binding, not a reason to replace it with a synthetic exec model.

4. **Route the existing leaf consumers after that API exists (rows 22/23).**
   `R/vcpu_loop/exec.rs::drive_execve` (called by `finish_prepared_execve`)
   currently obtains `mm_mutation::from_executor` and invokes the host image
   replacement. Its injected-engine suffix currently rejects suspension;
   owner Exec waits must be owned before that suffix, or its state machine
   must be converted to an owned continuation without retaining `&mut E`.
   An admitted route must instead borrow
   `from_owner_executor(&mut MmExecutorParticipation)
   -> Option<OwnerMmTopologyGuard<'_>>`, label it `ExecReplace`, and consume
   the owner Exec completion. `H/execve_rebuild.rs::execve_rebuild_inner`
   must consume that closed successor's physical completion instead of
   constructing `UserMemoryAuthority::from_legacy` and host tables.
   Only after all admitted callers migrate can
   `K/dispatch/mm_quiesce.rs::acquire_mm_stage1_authority` and sole/exact-MM
   acquisition reject admitted roots in their type boundary. Remove their
   admitted TLS/drain/editor path, `PtQuiesce::bind_mirror` bindings and
   host snapshots; preserve task ForkClosing, closed-root publication,
   execution/root occupancy and exact retirement proofs. Switching Exec to

   remove exclusion from a host writer, so this helper does not do that.

   The attempted editor-free `OwnerMmTopologyState` extraction was withdrawn
   during required verification. The reserved
   `K/dispatch/mm_authority.rs::mm_transaction_tests::
   mm_transaction_guard_construction_is_only_begin_transaction` requires

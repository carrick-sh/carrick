## Leaf changes

* `HvfTaskState::copy_guest_mapping_in` and `copy_guest_mapping_out` hold the
  existing legacy authority borrow through their last byte. An admitted
  root is refused before mapping selection, physical pinning or copying.
  They do not synthesize an owner transfer from the host's selected VA.
* `MappingSource::begin_access` also refuses an admitted root. A valid
  stage-2 generation cannot authorize this legacy semantic mapping API.
  Existing UserTransfer physical pins remain the admitted transfer route.
  Its lexical legacy borrow ends before the returned `BackingAccess` does;
  retained host reads **and writes** remain an open admission boundary.
* `backing.rs::read_backing_description(description, offset, length)` is the
  extracted, single implementation of source-byte reading. Its result is
  `BackingBytes { bytes, file_len }`; it has no MM, VMA, permission, guest VA
  or predecessor input. `snapshot_private_mmap_description` applies existing
  mmap EOF policy to that result. This keeps prior behavior while exposing
  the physical/semantic split to the integrator. The physical source witness
  verifies two distinct sources at identical offsets and beyond-EOF bytes
  without deriving a VMA fault.

## Retained legacy read/write admission — n1g and P2 obligations

Independent review of PR #14 found that the original lifetime handoff omitted
retained writes. `MappingSource::begin_access` drops its legacy read borrow
before returning `BackingAccess`. `HostWrites::begin` keeps that access in
`writes` until `HostWrites::finish` clears it, retaining content admission and
physical pins but no semantic admission. `UserMemoryAuthority` can therefore
switch to Owner while the host call still writes its old physical selection.
Later owner COW or protection changes make that selection unauthorized even
though the pinned storage cannot be recycled. The same transition must account
for escaped reads. Neither physical lifetime nor content coherence preserves
guest permission or translation authority.

n1g must land these changes together with P2's sealed transition:

* **`crates/carrick-vmm-hvf/src/trap/host_writes.rs`: `BackingAccess`,
  `MappingSource::begin_access`,
  `HostWrites::begin(&mut self, &HvfTaskState, &CarrierVmCustody,
  &[HostWriteRange]) -> Result<(), MemoryError>`, and
  `HostWrites::finish(&mut self)`.** Retain an owned, non-cloneable semantic
  access capability for the exact MM/incarnation and operation until the
  final read or write settles. Acquire it atomically with legacy admission
  before permission/translation selection; never allow a gap between the
  lexical borrow and retained capability. Carry it through every
  `BackingAccess`, the `HostWrites` vector, and the conversion into
  `HostReadRetention`. `finish`, partial-begin failure, cancellation, drop
  and unwind must release each capability exactly once, after the host call
  has stopped accessing its pointer and content settlement has completed.
  A cancellation request alone does not prove the host writer has stopped.
  Physical pin release does not substitute for this capability. Reuse the
  existing access path; do not add a second read/write implementation.
* **Reserved `crates/carrick-guest-mem/src/prepared.rs`:
  `UserMemoryAuthority::begin_selection`,
  `select_owner`, `admit_owner`, `promote_pending_with`, and
  `UserMemoryAdmissionGuard::select_owner`.** Root-shared admission must
  count retained legacy reads **and writes**, including holders reached
  through other task projections. Refuse before invoking any owner-selection
  or descriptor-publication callback while either kind is outstanding, or
  close new legacy admission and asynchronously drain existing operations
  before making Owner visible. Counter enrollment, closing and the
  zero-outstanding check must be one atomic authority transition. Refusal
  leaves the predecessor's bytes, permissions, translation and root
  occupancy unchanged; Pending promotion cannot bypass the drain. A stale
  or duplicate settlement cannot release a successor incarnation's hold.
  Use owned lifetime bookkeeping and an event-driven continuation on the
  existing wait service, not a lock held across host I/O, a queued writer,
  polling, or a guest executor blocked waiting for a host call.
* **P2 sealed transition and exec rollback.** Include both escaped reads and
  retained writes in the outstanding-access proof before retiring the
  legacy venue, consuming a bootstrap builder, opening a successor or
  publishing owner permissions/COW. Preserve the exact predecessor on an
  aborted transition, with operation cancellation and settlement tied to
  its MM/incarnation. Seal the types so an admitted handle cannot construct
  a host mapping editor or another legacy access. Removing a host mirror
  or revoking an executable receipt alone does not drain host writes.

The leaf fence permits the active VM-free witness
`n1_legacy_host_write_prevents_owner_admission_until_settlement` in
`crates/carrick-vmm-hvf/src/trap/guest_memory.rs`. It imports two actual MM
roots at identical VAs with separate compound backing and distinct
RW/read-only permissions. Production
`HostWrites::begin` retains an RW write; an attempted owner selection must
refuse or defer without invoking its publication callback or exposing Owner.
The simulated host call then completes four bytes through that retained
pointer and `HostWrites::finish` settles it.
Before reporting the admission failure, the witness checks the entire first
compound, the untouched peer compound, and both exact owner-tree permission
records. Once the lifetime boundary is fixed, its remaining assertions require
the exact Owner only after settlement (by a new selection or the completed
drain) and reject new legacy write admissions.
On this branch it reaches those byte/permission checks and fails with:

```text
legacy HostWrites crossed owner admission before finish; physical pinning did not preserve semantic admission
test result: FAILED. 0 passed; 1 failed; 0 ignored
```

n1g must additionally bind the same lifetime proof in the shared production
fixture: retain a read or write, attempt both initial selection and Pending
promotion, and prove their callbacks do not execute before settlement. After
settlement, admit and perform owner COW, read-only and PROT_NONE changes;
verify exact resulting bytes, permissions and peer isolation, and that no
old read/write capability can access the old physical selection. Exercise
partial-range begin failure, cancellation/unwind, and delayed duplicate or
stale completion against a successor. The leaf witness checks real physical
bytes and owner metadata, but does not synthesize descriptor/COW commits or
claim hardware AP/TLBI proof. Those production fixture and shared authority
changes remain reserved to n1g/P2. Both the new lifetime witness and the
original composite must turn green before N1 acceptance.

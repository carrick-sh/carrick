## Contracts and evidence limits

`N1-ROW26-SNAPSHOT` owns exact task/MM snapshot identity, complete parked
thread registers and sparse core serialization. Linux semantic authority is
the existing clean-room `core(5)`/AArch64 ELF core layout and the existing
core-dump tests. Work is proportional to enumerated VMAs, captured threads and
materialized bytes, never the virtual size of an untouched reservation. The
64 GiB fixture has exactly three reads of 4096 bytes and three payload extents.

`N1-ROW27-SIGNALFRAME` owns frame delivery faults, ucontext restoration and
interrupted-syscall restart. Semantic authority is the existing clean-room
Linux signal ABI codec and `sigreturn(2)`/`signal(7)` contracts. A failed frame
transfer must never activate the handler. Invalid sigreturn must never commit
registers or pop signal state. Frame bytes and register work are bounded by
the ABI frame size and architectural register count, with no host VMA walk or
unchecked-write fallback.

These are leaf witness names, **not registered completed contracts**. Contract
registration and production owner fixture binding belong to the integrator.
No owner handle was fabricated to make a fixture look production-connected.
No Docker, signed guest, performance, TLBI or whole-N1 acceptance is claimed.

## Red witnesses

Run from the repository root, after sourcing `/Volumes/carrick/dev/env.sh`:

```sh
CARRICK_RUN_ID=n1-p4-snapshot-red cargo test -p carrick-runtime n1_snapshot_includes_parked_el1_registers --lib -- --nocapture --test-threads=1
CARRICK_RUN_ID=n1-p4-signal-red cargo test -p carrick-hal n1_signal_frame_fault_and_sigreturn_use_owner --lib -- --nocapture --test-threads=1
```

Both exited 101, with `0 passed; 1 failed`. Logs:
`/tmp/n1-p4-snapshot-red.log`, `/tmp/n1-p4-signal-red.log`.

Snapshot failure:

> Snapshot must refuse a mismatched MM instead of publishing only the host vote

The newer base already reads the real EL1 parked save area. The fixture checks
the saved x0 and PC of a record bearing the exact thread serial, plus the
existing sparse capture work witness before the red assertion. A raw wrong-MM argument to
`CrashQuorum::open` yields `Complete` containing only the host register vote.
This is not evidence that parked registers are entirely unimplemented.

Signal failure:

> SignalFrame must use owner transfer, never prepare_host_write/write_bytes_unchecked

The observed count is **6**, expected **0**, across EINTR and SA_RESTART cases.
Both cases first verify the resumed x0/PC, restored SP/mask, invalid-PSTATE
sigreturn with unchanged registers, and a frame crossing an inaccessible page
with unchanged registers and bytes. The fixture's transport refuses the entire
frame on a fault; it does not prove a production owner partial-copy policy.
The transport spy is not an admitted-MM or exact-generation fixture.

These tests are neither ignored nor inverted into expected-success tests.
Consequently default HAL/runtime tests and the host acceptance gate remain
red until integration. Commands excluding exactly the new witnesses prove
existing-test compatibility only; they are not acceptance receipts.

## Leaf extraction delivered

- `R/vcpu_loop/crash.rs::append_core_bytes` takes `CoreFileOffset`, captured
  bytes, the remaining core storage budget and the output extent vector. It
  preserves the existing nonzero-run/RLIMIT_CORE serialization algorithm and
  has no guest address, mapping enumeration or memory-read authority. The
  existing capture loop now calls it instead of containing a second copy.
- `carrick_hal::sigframe::encode_sigframe<E: RegAccess>(&E, InjectParams)
  -> Result<SignalFrameImage, TrapError>` stages the existing Linux ABI bytes
  without guest memory access or register mutation. `SignalFrameImage` exposes
  `address() -> GuestVa`, `bytes() -> &[u8]`, and `saved_pc() -> GuestVa`; it is
  staging, not write permission or a completion receipt.
- `carrick_hal::sigframe::decode_sigreturn(GuestVa, &[u8])
  -> Result<ValidatedSigreturn, TrapError>` performs the existing ucontext
  decode/PSTATE validation before register mutation. The decoded value exposes
  `sigmask() -> SigSet` and `saved_pc() -> GuestVa` and cannot be constructed
  with unchecked public fields.
  Existing build/restore functions call these codecs. Rosetta's Linux-shaped
  frame without the private Carrick magic remains accepted. The leaf preserves
  the existing low-four-bit PSTATE and FPSIMD-magic checks; it does not add full
  Linux register/extension-record validation or authenticate the supplied bytes.
- `K/kernel/objects/signal.rs::ThreadSignalState::enter_handler(&mut self,
  handler_mask: SigSet, on_altstack: bool) -> SigSet` contains the existing
  saved-mask consumption, blocked-mask update and handler-frame push as one
  leaf state operation. The dispatcher delegates to it; RESETHAND ordering
  and all current effects are preserved.

No owner transport, host registry, host memory authority, ABI variant, export
registration or fallback was added. Existing host routes remain unconverted,
not accepted alternatives for admitted roots. Frame construction/validation
still executes on the host until the integrator relocates this one codec.

## Required n1g changes: row 26

**Shared service signature to settle** (proposed vocabulary, not an existing
API):

```rust
fn request_core_snapshot(
    context: &KernelContext,
    owner: El1MmHandle,
    capture: CrashCaptureGeneration,
) -> Result<OwnerCoreSnapshot, CoreSnapshotError>;
```

`OwnerCoreSnapshot` must be a move-only frozen owner result retaining exact
`TaskKey`, every `ThreadKey`, owner carrier/MM/incarnation, the capture
generation and freeze custody. Authenticate them before collecting anything,
and refuse mismatched/retired generations explicitly. A perpetual `Waiting`
response is not a fix for the red witness. Thread registers must come from
the exact EL1 save area when parked, not a host executor or its numeric tid.

Its manifest must enumerate owner VMAs, file provenance and sparse materialized
subranges. Each bounded byte read must consume a snapshot-issued physical
lease under that same freeze. No host `MemoryProtections`, manager snapshot,
`deferred_anonymous_state`, guessed VA-to-IPA or re-enumeration may supply
admitted-root truth. A short byte completion must fault, not silently shorten
a declared extent. Retirement, cancellation and Drop release the same freeze
and physical leases, with no host-table rollback.

In reserved `A/engine.rs`/HAL/ABI and the owner portal, provide the Snapshot
operation and backend binding. In this leaf's
`ThreadRuntimeState::capture_core_for_publication`, replace admitted use of
`prepare_core_snapshot`, raw `CrashQuorum::open`, host VMA/deferred manifests
and `read_core_bytes` with that single owner result. Feed only its captured
bytes to `append_core_bytes` and the existing core serializer. Contained file
publication remains a host effect.

Bind `n1_snapshot_includes_parked_el1_registers` to this production request,
preserving its exact parked-record and sparse assertions. Upgrade the current
negative `!Complete` assertion to the settled explicit identity-refusal error.
Add same-VA two-MM, stale MM incarnation, recycled thread serial, exec during
capture and cancellation tests to the production fixture. The present raw
quorum API cannot represent MM incarnation or an explicit refusal; changing
only its numeric MM check would not close the row.

## Required n1g changes: row 27

**Owner operation signatures to settle** (proposed, not a second implemented
interface):

```rust
fn deliver_signal_frame(
    context: &KernelContext,
    owner: El1MmHandle,
    injection: SignalInjection,
) -> Result<SignalFrameCompletion, OwnedSignalFrameOutcome>;

fn restore_signal_frame(
    context: &KernelContext,
    owner: El1MmHandle,
    frame_sp: GuestVa,
) -> Result<SignalReturnCompletion, OwnedSignalFrameOutcome>;
```

Use the existing portal's explicit **SignalFrame** intent, not UserWrite plus
an unrestricted unchecked writer. Move the one codec into an owner-callable
shared core/EL1 layer; HAL cannot itself become an EL1 dependency. No copied
frame builder/restorer may remain alongside it. The completion authenticates
exact task/thread execution generation and MM incarnation through all chunk
reads/writes, parked-service access and register publication.

The ABI frame is larger than the current 4096-byte portal chunk. Preserve one
owned frame operation across chunks and pre-effect suspension; retain byte
offset and exact completion custody, never restart a completed prefix at zero.
Freeze/prepare all pages before handler activation. If Linux permits a visible
written prefix on a later-page fault, define and test that prefix precisely;
no success completion or handler/mask activation may follow the fault. Test
both an unmapped and PROT_NONE second page on an alternate stack, same VA in
two live MMs, and delayed completions after exec/retirement. Do not turn wait,
supply or retirement into a generic SignalDeliveryFault/EFAULT.

Replace reserved `A/engine.rs::{inject_signal,restore_from_sigframe}` and
`R/vcpu_loop/signal.rs::deliver_signal_with_restart`/fault delivery with this
owner operation. Linux restart decisions and frame validation must be in the
owner, including saved original x0/SVC PC versus an interrupted EL0 PC.
Only a successful frame completion may consume the saved-mask arm, call the
extracted handler-state transition or apply RESETHAND.

There is a second necessary shared change: currently
`K/dispatch/signal.rs::rt_sigreturn` pops the handler frame **before** the
reserved `R/vcpu_loop/binding.rs` SigReturn arm calls
`engine.restore_from_sigframe`. Move that pop to successful owner completion,
together with mask restoration. Update `R/runtime.rs`'s SigReturn arm too.
The leaf dispatch code must change in the same integration commit, not alone.
Invalid sigreturn must leave registers, masks and handler depth unchanged
until the owner emits the Linux forced-fault result.

Bind `n1_signal_frame_fault_and_sigreturn_use_owner` to the production owner
fixture, keeping its fault/no-activation, invalid-return and restart assertions
and zero legacy-hook count. Add the exact-generation and permitted-prefix
checks above. Merely swapping unchecked writes for ordinary checked writes
could satisfy the spy but would not implement this owner contract.

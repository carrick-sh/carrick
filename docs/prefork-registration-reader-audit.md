# Prefork registration production reader audit

The scanner was not the only defect. Shared process-table consumers used
leading publication/generation checks followed by unprotected body loads.
Acquire publication proves initialization; it does not retain a lifetime.
Process-local namespace mutexes do not exclude another host process's reap.

Search scope: `git grep` across **all crates** for `ProcessSection`,
`ProcessRecord`, `ProcessRecordRef`, `layout().processes`, `find`, indexed
`records`, and record iterators. The only production process-table body users
are `carrick-host/src/guest_cpu.rs`, `carrick-kernel/src/namespace/pid.rs`, and
`carrick-kernel/src/run_state.rs`, plus the arena implementation itself.
Other `.processes` hits name kernel graph collections or budget counters.
There are no direct in-tree production calls to `ProcessSection::find`:
production uses equivalent hand-written child, namespace and run-state scans.
The exported arena lookup is nevertheless hardened and now has an owned read
API for consumers.

The table lists each lookup/body consumer, including the internal helpers that
establish protection. Scalar accessors (`record_parent_pid`, `record_guest_ns`,
`record_virtual_ptrace_control`, etc.) inherit the protection of the enclosing
consumer, and never provide lifetime authority themselves. Test-only raw
record accesses and test-only ptrace control commands are excluded from the
production inventory.

These are lifetime-consistent **owned observations**, not pins. A process can
exit immediately after a successful lookup; subsequent mutating operations
must still acquire exact transition/control authority. The callback rejects
release and same-numeric-PID reuse, but does not claim a transaction over
ordinary live-generation metadata changes (e.g. a run-state update).

Deterministic negative control: disable only trailing `read_record` validation.
The arena returns `(77, 88, 0)` after a forced reap; namespace translation
returns `(88, 0)`; the child reader returns old namespace identity with the
replacement parent; run-state rendering returns the replacement's `Blocked`
state after observing the old identity. Every corresponding assertion fails.
Restoring validation returns `Stale`/absence through these same production
paths. A separate cross-host fork releases the shared record mid-read, and a
same-PID reuse test ensures equal numeric PID does not defeat the check.

The original storm keeps its scanner, 200 children and immediate reuse, and now
uses the exact same validated production read. There is no test-only observer
mutex, retry, sleep, expanded deadline or concurrency reduction.

Baseline lint comparison: a detached scratch checkout of `origin/main`
`9cbe10d75` passed `just lint-domains` (exit 0). This does **not** confirm the
previous branch-runner matrix failures on main; no host-authority machinery
was changed to explain or suppress them.

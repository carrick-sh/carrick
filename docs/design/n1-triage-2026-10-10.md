### Architectural Context

The N1 draft work represented Carrick's initial architecture for delegated EL1 memory management and host-orchestrated process execution (`carrick-vmm-hvf/src/trap/{owner_fork,process_plan,cow_engine,foreign_mm}.rs`, `carrick-aarch64/src/fork.rs`, and `FaultSupply::Mailbox` in `frame_mailbox.rs`).

Between 2026-10-06 and 2026-10-08, Carrick adopted the **shared-kernel inversion and ring-first flip** (PRs #104-108, #120, #121, `docs/design/arm-ring-first-flip.md`):
1. The in-ring shared kernel (`carrick-el1` / `carrick-x86-cpl0`, `carrick-sched-core`, `carrick-personality-linux`) took direct authority over process lifecycle, signals, and virtual memory.
2. In-ring execution replaces host fork planning and host COW fallbacks. Wave D (Package P16 in `docs/audits/code-structure-audit-2026-10-10.md`) explicitly deletes the host ARM fork and COW files.
3. Several N1 fixes have already landed on main under new commits (e.g. `0565ec758` and `bbf545fd4` ported as `6f0db0dc4` in PR #128; `025c4a558` landed in PR #106 `d6112d748`).
4. However, a cluster of critical fixes—particularly in `carrick-sched-core` space coordination, `carrick-runtime` completion handbacks, `carrick-el1` advisory `MAP_STACK` reservations, and `carrick-kernel` sleep expiration—remain unported and directly applicable to main.

### Package 1: Sched-Core Space Coordination & Lost-Wake Fixes (P0 - Critical Concurrency)
- **Category:** `PORT`
- **Source Commits:** `cad5ae1f8d`, `b05cc42149`, `8f7cbc1a0c`
- **Target Files:**
  - `crates/carrick-sched-core/src/spaces/notification.rs`
  - `crates/carrick-sched-core/src/spaces.rs`
  - `crates/carrick-core-abi/src/wait.rs`
  - `crates/carrick-runtime/src/vcpu_loop/reservations.rs`
- **Description & Scenario:**
Fixes three race/hang conditions in `carrick-sched-core`:
1. **`cad5ae1f8d`:** Unlocks resource words (`word.store`) in `ResourceRelease::new`, `release_gate`, and `SpaceEditor::drop` *before* advancing the cause revision. Previously, revision advancement preceded unlocking, creating a race window where concurrent threads observed the new revision, failed to acquire, and parked indefinitely on already-unlocked resources.
2. **`b05cc42149`:** Adds `editor_held()` check in `PortalWaitEnrollment::park_host` to re-validate that the active editor is still held before parking on the host, preventing threads from parking on an already-vacated editor.
3. **`8f7cbc1a0c`:** Implements `SpaceAccess::publish_metadata` and wires `CarrierReservations::provision_metadata` to wake threads parked on `SpaceWaitCause::Metadata`, eliminating stalls in sibling threads waiting on metadata capacity.
- **Guest-Visible Scenario:** Intermittent or deterministic hangs under multi-threaded contention during memory allocation, socket IPC (`sock-pingpong`), or parallel thread execution.
- **Conflicts & In-Flight PR Dependencies:**
- **PR #131 (signals):** Zero conflict (no overlapping files).
- **PR #137 (IPC):** Touches `vcpu_loop/reservations.rs`. Can land `sched-core` parts immediately; coordinate `provision_metadata` with PR #137.
- **x86 fork landing / ARM COW lane:** Zero conflict.

### Package 2: VCPU Executor Completion Handback Drain (P0 - Livelock Fix)
- **Category:** `PORT`
- **Source Commits:** `d221b3d491`, `751b0ec63e`, `3f0762f658`
- **Target Files:**
  - `crates/carrick-runtime/src/vcpu_loop/executor/backend.rs`
  - `crates/carrick-sched-core/src/completion_queue.rs`
  - `crates/carrick-el1/src/sched/object_wait.rs`
- **Description & Scenario:**
Fixes an idle-exit livelock and lost wake during deferred completion handbacks:
- When a guest thread finishes an object wait (e.g. MM wait), completion handbacks are deferred to `zone.completion_handbacks`. Idle vCPUs previously checked only `pending_host_work`, missed handbacks, and entered WFI. When exiting with `Action::Idle`, the host executor loop failed to drain handbacks, leaving vCPUs bouncing indefinitely.
- **`d221b3d491`:** Adds `has_pending` to `CompletionQueue`, prevents EL1 vCPUs from entering WFI when handbacks are pending, and wakes idle vCPUs via reschedule SGIs.
- **`751b0ec63e` / `3f0762f658`:** Drains `hand_back_completions()` at the exact host executor idle return boundary in `backend.rs:wait_in_guest`.
- **Guest-Visible Scenario:** Multithreaded execution hang / watchdog timeout in `el1_sched_host_blocked_read_resumes_by_guest_scheduling`.
- **Conflicts & In-Flight PR Dependencies:**
- **PR #131 (signals) & PR #137 (IPC):** Zero conflict.
- **x86 fork landing / ARM COW lane:** Zero conflict.

### Package 3: Advisory MAP_STACK Reservation in EL1 (P1 - Conformance & Crash)
- **Category:** `PORT`
- **Source Commits:** `853534225f`, `b5980416dc`
- **Target Files:**
  - `crates/carrick-el1/src/memory.rs`
- **Description & Scenario:**
- **`853534225f` (supersedes `b5980416dc`):** Treats `MAP_STACK` as an advisory hint in `carrick_el1::memory::decide_anonymous_syscall` rather than rejecting/forwarding it to the host.
- **Guest-Visible Scenario:** Musl libc and Rust `std::thread` allocate thread stacks with `mmap(MAP_PRIVATE | MAP_ANONYMOUS | MAP_STACK)`. On main, forwarding this mapping leaves it unmapped in the admitted EL1 root; the first stack touch triggers a host sparse fault that delivers `SIGSEGV` to the guest task.
- **Conflicts & In-Flight PR Dependencies:**
- **PR #131 (signals) & PR #137 (IPC):** Zero conflict.
- **x86 fork landing / ARM COW lane:** Zero conflict.

### Package 4: Continuation Sleep Expiration Preserves Remaining Output (P1 - Conformance)
- **Category:** `PORT`
- **Source Commits:** `2d5c588c8f`
- **Target Files:**
  - `crates/carrick-kernel/src/kernel/continuation.rs`
- **Description & Scenario:**
- In `BlockedContinuation::resume` for `ContinuationFamily::WaitOnSleep`:
  - Linux semantics dictate that `nanosleep` and `clock_nanosleep` write remaining time to `*rem` *only* when interrupted by a signal, never upon successful timeout expiration.
  - Main currently returns `ReturnWithGuestWrites(0, ...)`, zeroing the `rem` struct in guest memory on successful expiration. This causes unnecessary memory writes, potential EFAULTs on read-only buffers, or user memory corruption.
  - Fix sets `ContinuationCompletion::Return(0)` for `WaitOnSleep` timeouts.
- **Guest-Visible Scenario:** Incorrect modification of `rem` buffer on successful sleep; false EFAULT if `rem` points to read-only or guarded memory.
- **Conflicts & In-Flight PR Dependencies:**
- **Code-Structure Audit P4:** Touches `continuation.rs`, but affects disjoint functions (`prepare_blocked_continuation` vs `resume`).
- **PR #131 & PR #137:** Zero conflict.

### Package 5: VFS System Call Atomicity & Error Handling Red Tests (P2 - Conformance Probes)
- **Category:** `RED-TEST`
- **Source Commits:** `919bb7e231`, `3df4a205f2`, `d559ef7b41`, `07081da640`, `807f5f8589`
- **Target Files:**
  - `crates/carrick-kernel/src/dispatch/fs/directory.rs`
  - `crates/carrick-kernel/src/dispatch/format_stat.rs`
  - `crates/carrick-kernel/src/dispatch/fs/pipe.rs`
  - `crates/carrick-kernel/src/dispatch/fs/xattr.rs`
  - `crates/carrick-kernel/src/dispatch/fs/ioctl.rs`
  - `crates/carrick-kernel/src/dispatch/format_time.rs`
- **Description & Scenario:**
Writes red-first test witnesses against main for VFS system call atomicity defects identified in N1:
1. **`919bb7e231` (Getdents offset corruption):** `getdents64` in `directory.rs` increments `*offset` before `memory.write_bytes` succeeds. If copyout fails (e.g. invalid buffer), `*offset` remains incremented. Subsequent calls skip directory entries. Witness: `getdents64(fd, NULL, count)` -> `-EFAULT`, then `getdents64(fd, valid_buf, count)` -> assert `.` and `..` not skipped.
2. **`d559ef7b41` (Pipe descriptor leak):** `pipe2` creates file descriptions before copying fds to guest memory. If writing to `pipefd` fails with EFAULT, descriptors leak into the task's fd table. Witness: `pipe2(invalid_ptr, 0)` -> `-EFAULT`, verify open fd count and table capacity unchanged.
3. **`3df4a205f2` (Stat copyout):** Verify stat/fstat copyout fault returns `-EFAULT` without modifying description state.
4. **`07081da640` / `807f5f8589` (Input copy atomicity):** Verify that pathname / ioctl parameter reading faults cleanly reject the syscall before any destructive kernel state change.
- **Conflicts & In-Flight PR Dependencies:**
- **PR #131 & PR #137:** Zero conflict (all files in `crates/carrick-kernel/src/dispatch/fs/`).
